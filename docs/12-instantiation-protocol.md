# 实例化协议

本协议是实施 AI 的操作顺序。跳过确认直接生成完整实现，视为未完成。

## 输入

人提供：

- 本蓝图目录
- 目标业务的仓库地址，或已经 clone 的只读副本
- 能回答主干名、谁验收、什么算发布的人

人未提供的 Git 主机、身份系统、依赖源、模型供应商，一律视为未知。

## 阶段 A — 绑定

1. 按 README 的顺序读完本蓝图。
2. 只读查看每个候选仓库：远程 HEAD、语言、如何构建、如何测试、保护分支、入口目录。
3. 起草绑定：配置、领域总览、改动索引、各仓介绍、实例版 `AGENTS.md`。
4. 列出未知项，向人提问。问题只问绑定合同里的空缺。
5. 人确认绑定之前，停止。

阶段 A 的产物放在 **新的实例目录**，不要写回本蓝图。

完成标准：配置里没有占位符；每个仓库的 `baseBranch` 与远端一致；验证命令是从该仓现有脚本抄来的，或明确写成没有测试；领域文档覆盖改动索引。

## 阶段 B — Kernel

在实例目录实现命令，并先写测试：

| 测试 | 期望 |
| --- | --- |
| 已有 working 迭代时再 new-iteration | 失败，输出当前 id 与收口方式 |
| 脏工作区 checkout | 失败，列出文件 |
| 从主干创建分支 | 分支指向刚 fetch 的提交；同名分支第二次失败 |
| 符号链接仓库 | check 失败 |
| 无回执时进入开发 | 失败 |
| dev 不带仓库、或带两个仓库 | 失败 |
| 未确认的 publish | 只生成计划，保护分支不变 |
| 确认者是模型自签或身份不足 | 失败 |
| 活动文件与锁不一致 | check 失败，并说明以锁为准 |

命令行为以 [模块与命令合同](13-module-and-command-contract.md) 为准。

完成标准：上述测试在临时 Git 仓库中通过，不接触真实业务远端的写操作。

## 阶段 C — 对话、队列与 Host

1. 实现访问口令会话、需求对话、需求卡版本、确认入队。
2. 普通问候不建任务。
3. K1 忙碌时入队并返回人话原因。
4. 阶段产物按工作流生成，确认命令核对对齐开关。
5. 关掉客户端再查询，任务仍在。
6. 取消进行中任务需要两次确认语义，并释放锁。

对齐审查可以先做成可注入的审查器。默认实现必须拒绝「作者自报通过」。

## 阶段 D — 编码与验收

1. 接入编码模型。工具面只有合同允许的 Kernel 操作。
2. 用临时 Git 样板跑通：方案确认 → 指定文件写入 → 旧哈希不符被拒绝 → 配置的验证 → 未验收不提交。
3. 再对一个低风险的真实仓库任务，由人确认方案后执行。
4. 预览只挂验证通过的产物。地址未配置时不编造。

自动编码在阶段 D 的临时样板通过、且人显式打开开关之后才对真实仓库生效。

## 阶段 E — 可选项

证据源、统一登录反代、即时通讯适配器、风险归档，都在主路径可用之后单独加。每一项都不得新增状态机或放宽 K1–K10。

## 实例目录形状

```
<instance>/
  AGENTS.md
  README.md
  automation.config.json
  .env.example
  docs/domain-overview.md
  docs/change-map.md
  docs/repositories/<key>.md
  iterations/.active.md
  templates/
  commands/                 Kernel
  host/                     HTTP 与会话
  web/                      提出人界面
  test/                     闸门测试
  target-repos/             gitignore
  runtime/                  gitignore
```

实例的 `AGENTS.md` 使用 [`blueprint/AGENTS.instance.md`](../blueprint/AGENTS.instance.md) 的结构，把尖括号说明换成该业务的事实。

## 完成定义

同时满足才算一个可用实例：

- 绑定已由人确认
- 阶段 B 的闸门测试通过
- 提出人可以在 Web 上把一条需求确认进队列，并在已有任务时看到排队原因
- 没有确认回执时，编码工具的写入被拒绝
- 业务源码不在 Agent 仓库的版本历史里
- 密钥不在仓库里
- README 写明如何启动 Host、如何检查、当前实例不做什么

## 不得做的实现捷径

- 把蓝图示例书店当成真实领域
- 复制另一个业务的仓库清单、主机名或验证命令
- 用聊天记录代替 `confirmations`
- 让模型在提示词里承诺遵守 K1，却不在命令里检查
- 为了演示而把保护分支的推送默认打开
- 在不够到该业务 Git 和依赖的环境里修改 `target-repos`

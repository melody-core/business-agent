# 已锁定决策

这些决定对所有实例有效。实施时不再展开成可选项。

| 题目 | 决定 | 原因 |
| --- | --- | --- |
| 状态放哪 | `iterations/` 与 `runtime/` 的文件 | 重启可恢复，Agent 仓库的档案可审计 |
| 谁改世界 | Kernel 命令 | 通道和模型都会漏掉口头约束 |
| 同时几条任务 | 一条 working 或 blocked | 一份可写副本无法安全并行 |
| 分支从哪来 | 各仓刚 fetch 的 `origin/<baseBranch>` | 本地主干会过期；主干名因仓而异 |
| 业务是否预选仓库 | 否 | 提出人描述目标；影响面在方案里纠正 |
| 业务主入口 | Host 上的 Web | 任务时长不适合只活在 IDE 或即时通讯里 |
| 适配器 | 只转发 | 第二套状态机会和 Kernel 分叉 |
| 确认 | 带版本哈希的回执 | 聊天里的同意无法被下游命令核对 |
| 对齐 | 默认开启，服务端计算通过 | 作者不能批准自己的「已对齐」 |
| 自动编码 | 开关，且逐次校验 | 打开不等于授权改范围外的文件或发布 |
| 发布 | 默认交接 | 保护分支的推送权留在 operator 的显式确认 |
| 预览 | 已验证的不可变产物；地址可空 | 未配置时不编造可访问地址 |
| 可写副本 | Host 一份 | 避免两台机器互相覆盖 |
| 运行环境 | 必须够到该业务的 Git 和构建依赖 | 够不着的环境只做与业务仓无关的事 |
| 业务源码 | 独立 clone，不进 Agent 仓库，不用符号链接 | 符号链接会把别的工作区误当成 Host 的副本 |
| 密钥 | 环境变量与受限运行时目录 | 配置和档案会被复制、展示、送进模型 |
| 维护任务 | 有界，做完就收口 | 进行中通道不是待办列表 |
| 外部变更单 | 可选后置 | 不阻塞从主干拉分支 |
| 证据与日志 | 可选模块 | 没有证据源的业务仍能走需求主路径 |
| 登录 | 先访问口令 | 统一登录放在前面的代理，不改任务模型 |

未锁定、必须问目标业务的事项都在 [绑定合同](11-binding-contract.md)，不在本表。

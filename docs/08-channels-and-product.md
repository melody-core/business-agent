# 通道与界面

## 通道

| 通道 | 角色 | 约束 |
| --- | --- | --- |
| Web | 业务主入口 | 只调 Kernel API |
| 研发 IDE | 审代码、在接管时改代码、维护 Agent 仓库 | 改业务仓仍受同一把锁和同一组命令约束 |
| MCP 或同等工具协议 | 把同一 Kernel 暴露给其他 IDE | 工具名与命令一一对应，不另做状态机 |
| 即时通讯适配器 | 可选 | 只做身份映射、把消息变成任务消息、把确认和预览链接送回。阶段机仍在 Kernel |

Web 优先。适配器未接入时，HTTP 合同已经存在，适配器是空实现。

## 会话

通道身份映射到 viewer、requester、operator、admin。Git 身份使用 Host 上的部署凭证，只能读写绑定中列出的仓库。

预览和业务系统的登录凭证放在 Host 的密钥存储。Agent 只知道「需要登录」，不把口令写进迭代文件。

P0 用访问口令进入 Web。会话可以持续数天，重启后仍有效。修改口令或退出使相应会话失效。

若以后要接统一登录，放在 Host 前面的反向代理。任务模型、确认模型和文件布局不变。

## 信息架构

桌面三栏；窄屏改为上列表、中对话、下决策。

```
左：任务列表          中：当前任务时间线         右：决策区
  新需求                提出人的话                 当前步骤（业务语言）
  进行中 / 等你确认      进展                       确认卡
  排队                  输入框                     预览入口
  已完成                                            阻塞：卡在哪、找谁
```

- 选中任务等于打开这条线程。
- 空态只有输入。不先填表，不先勾选仓库。
- 右侧只放需要人决定或需要人看的结果。不放文件树、终端和逐行注释。
- 输入框默认属于当前任务。只有明确「新需求」才可能进入队列。

影响面可以展示成「打算改哪些入口」。那是判断结果，不是开任务前的必填项。判断错了，用「要改」纠正，然后重新确认受影响的阶段。

## 提出人看见的进展

| 提出人看见的 | 背后 |
| --- | --- |
| 已收下需求 | 需求卡已确认并入队或已开始 |
| 正在准备这次改动 | 从最新主干创建功能分支 |
| 方案等你确认 | 阶段产物 + 对齐通过 + 确认卡 |
| 正在改功能 | 编码运行时在允许范围内写入 |
| 可以看效果了 | 已验证产物的预览 |
| 需要你处理 | 外部阻塞，写明处理方 |
| 请研发发布 | 交接计划，等待 operator |

编码过程不把文件级差异当作业务界面的主体。提出人追问「改了什么」时，用几句话说明行为和规则变化，并允许研发旁路打开真实差异。

## 确认卡

确认卡包含：阶段名、这一版全文、相对上一版的变化、对齐结果、同意 / 要改。

「要改」把意见写回对话，生成下一版，旧回执失效。

直接 API 确认与页面确认走同一条 Kernel 命令，同样核对身份、阶段、版本和对齐状态。

## 排队文案

已有进行中任务时，新需求的说明要包含当前任务标题、新需求已排队、当前任务不会被冲掉。不展示工程堆栈，不要求提出人执行命令。

维护占用只显示「工作台维护占用」，不泄露其他用户的内容。

## 取消与移出

取消进行中任务的交互见 [问题与产品](01-problem-and-product.md)。后台对应 `abandon` 并释放锁。页面不出现 Git 命令。

移出尚未开始的排队项只需一次确认。

## 多提出人

P0 可以是共享口令下的单一操作者。要区分多人时，每个会话绑定身份：

- 只能读取自己的需求原文和他人任务的状态摘要，除非角色允许。
- 不能确认或取消别人的任务。
- 队列统计按身份过滤。

## 进度传输

长操作使用可恢复的事件流。页面按事件序号重连。停止按钮取消这一轮运行。刷新和切换页面不取消。

Host 重启会中断运行中的模型轮次，但保留问题、已落盘证据和阶段产物。恢复后不把中断显示成完成。

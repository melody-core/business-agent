# 验证、预览与验收

## 三种证据

| 种类 | 证明什么 | 不证明什么 |
| --- | --- | --- |
| 构建或编译 | 按配置的命令可以产出 | 不证明行为正确，也不证明测试跑过 |
| 自动测试 | 配置范围内的用例结果 | 不证明验收条目被业务认可 |
| 业务验收 | 提出人对每条验收标准的结论 | 不代替未配置的自动验证 |

三者分开记录。任一缺失、失败、过期，都不能互相填补。

## 命令归属

每个仓库在绑定里声明验证：

- 构建命令、参数、超时、产物目录
- 测试命令、范围如何从已确认的文件推导
- 测试是否必须

Kernel 从已确认实施方案的文件推导范围，例如「变更所在的包」。模型不能改命令、不能改范围、不能筛掉失败用例。

未配置测试执行器的仓库，不得把构建成功标成测试通过。未配置的验证器不得用任意 Shell 或模型猜测代替。

环境要可重复：记录实际的语言版本、平台和策略版本。策略变化使旧证据失效。离线或只读依赖模式若被声明，就不得在验证时悄悄下载。这不等于进程级网络沙箱；会连接真实外部系统的测试必须在绑定里标明，并默认不能当作纯单元证据。

## 验收条目

验收项分成两类：

- **工作台可验证**：绑定了仓库、包或用例名。通过后自动勾选，人不能改成失败之外的另一个结果。失败、零用例、跳过、缺少绑定、覆盖不完整，都不是通过。
- **需要人工**：人填写实际观察。最终「验收通过并保存交付」仍由人确认。

绑定由维护者写在配置里，按需求版本和验收文本精确匹配。浏览器或模型不能自报通过。

未知但看起来像本地测试的条目，保留为待绑定。无法确定的条目保守地留在人工核对。

## 预览

预览默认使用 **验证成功后冻结的产物**，而不是一边改文件一边看的开发服务。开发服务可以作为研发旁路，不作为验收所依据的地址。

- 预览地址来自配置。未配置时显示「预览地址待配置」，不猜测本机地址。
- 每个版本有独立地址，并校验产物校验和与任务归属。
- 没有页面的交付不伪造页面预览，验收走人工项或接口证据。
- 一次只预览一个仓库的产物。

提出人看到的是「可以看效果了」。源站可以是 Host 上的独立端口，或部署时填写的反向代理源。

## 保存交付

「验收通过，保存交付」在全部自动项通过、人工项已填写、对齐与指纹仍有效时，在各业务仓的功能分支上创建 **本地提交**。记录验收人、时间和预览版本。

它不推送、不合并、不发布。

多仓保存若中断，可以继续保存。已经成功的提交复用；源码已经变化则拒绝覆盖式继续。

## 发布

默认 `publish` 只写 `publish-report.md`：仓库、分支、提交、目标环境、需要人做的动作。

显式 `publish --confirm` 且身份为 operator 或 admin 时，才可以按绑定把功能分支推进已声明的非生产共享分支。生产环境默认仍只交接。

确认绑定源码提交与目标分支的预期头。推送前工作区干净，功能分支已提交。

业务发布若导致 Agent 仓库自身也有文档或命令变更，这些变更走 Agent 仓库自己的保护规则，不混进业务仓提交。

发布后的流水线结果另行核实。Agent 不把「推送已发出」写成「环境已更新」。

## 风险归档

正常闸门之外，可以存在一条独立的风险归档：人明确接受某些未通过的验证或未核对项，并留下原失败记录。

风险归档：

- 不会被自动编码或对齐失败触发
- 不扩大文件写入范围
- 不把生产发布变成自动
- 页面上与普通通过区分开

## 外部阻塞

权限、账号、私有依赖、网络策略、第三方环境写在 `external-blockers.md`：缺什么、证据、谁能解除、解除前哪些阶段不能继续。

外部阻塞不是代码失败。不通过反复改代码消化它。

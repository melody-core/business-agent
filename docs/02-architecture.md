# 架构

## 一句话

Web 是遥控器，Host 是备好的环境，Kernel 是唯一能改世界的手。

## 分层

```
                    ┌──────────── 通道层 Channel ────────────┐
                    │   Web 工作台   │  研发 IDE  │  可选适配器  │
                    └──────┬─────────┴─────┬──────┴──────┬─────┘
                           │               │             │
                           ▼               ▼             ▼
                    ┌──────────── 会话层 Session ────────────┐
                    │  鉴权 · 身份与任务绑定 · 确认回执投递     │
                    └──────────────────┬─────────────────────┘
                                       ▼
                    ┌──────────── 编排层 Orchestrator ───────┐
                    │  队列 · 单任务锁 · 阶段机 · 心跳与恢复    │
                    └──────────────────┬─────────────────────┘
                                       ▼
              ┌────────────── 内核 Kernel ───────────────────┐
              │  check / init / new-iteration / checkout     │
              │  confirm / dev / test / complete / publish   │
              └──────────────────┬───────────────────────────┘
                                 ▼
              ┌────────────── 执行层 Runtime ────────────────┐
              │  编码模型只通过受控工具改已登记仓库            │
              └────────┬──────────────────────────┬─────────┘
                       ▼                          ▼
              Agent 仓库（迭代档案、规则）     target-repos/<key>
```

| 层 | 职责 | 不做 |
| --- | --- | --- |
| Web | 任务列表、时间线、确认卡、预览入口、阻塞说明 | 不实现阶段机，不直接改 Git |
| API | 鉴权、把「新需求」翻译成 Kernel 调用、推送进度 | 不直接改 Git |
| Orchestrator | 判断消息属于当前任务、排队还是拒绝；推进阶段指针 | 不把进度只放在进程内存 |
| Kernel | 不变量、分支、确认、验证、发布 | 不渲染页面 |
| 编码运行时 | 在功能分支上按已确认清单改文件并等待验证 | 不自签确认，不推送保护分支 |
| 卷与密钥 | 持久化任务、锁、队列和凭证 | 不进入 Git |

研发 IDE 与 Web 调用 **同一套 Kernel**。页面上的任务和 `iterations/<id>/` 是同一件事。

## 四条铁律

1. **通道只通过 Kernel 改变世界。** 浏览器、IDE 插件、即时通讯适配器都不直接 `git` 写业务仓。
2. **编码模型不绕过 Kernel。** 建任务、拉分支、完成、放弃、推送保护分支、写入业务文件，都要经过命令校验。
3. **文件是状态源。** 可恢复的事实在 `iterations/` 与 `runtime/`。进程重启后从这些文件继续。模型上下文和聊天历史不是状态源。
4. **一份可写副本。** 每个已登记仓库在全环境只有一份可写工作区，放在 Host 上。其他人审查远端功能分支，或在该任务期间把写锁交给指定的人。

## 三份世界

| 位置 | 内容 | Git |
| --- | --- | --- |
| Agent 仓库 | 命令、规则、领域文档、迭代档案、模板 | 提交。不提交业务源码 |
| `target-repos/<key>/` | 已登记业务仓库的独立 clone | 不提交进 Agent 仓库。业务提交只发生在各仓自己的历史里 |
| `runtime/` | 锁、队列、心跳、事件、密钥、日志 | 不提交 |

`iterations/.active.md` 是给人和其他 Agent 读的活动任务投影。与锁不一致时，**以锁为准**，检查报失败并给出修复方式。

## 物理拓扑

| 角色 | 职责 |
| --- | --- |
| Agent Host | 跑编排、Kernel 和编码运行时。能访问该业务的 Git、依赖源和验证所需的网络。至多启动一个业务服务 |
| 研发坐席 | 审查 Host 推送的功能分支，或在接管期间独占写锁 |
| 提出人 | 浏览器访问 Host。看进度、确认、验收 |

两台机器不得同时可写同一 `target-repos/<key>`。研发必须在自己机器上改代码时，该任务期间 Host 执行接管：锁的持有者改为人，编码运行时停止写入。

Host 用容器或等价的可复制环境均可。选择标准只有一条：这个环境必须够得着该业务的源码和构建依赖。够不着的托管环境只允许做与 `target-repos` 无关的文档任务。

## 编码运行时与 Kernel 的分工

编码运行时负责模型对话、线程恢复和受控工具调用。Kernel 负责任务状态、方案版本、分支、允许写入的路径、旧文件哈希、验证命令和发布。运行时的工具授权不能代替产品里的确认回执。

## 部署形状

一个 Host 进程提供：

- Web 静态资源
- 任务、确认和进度 API
- Kernel 命令
- 可选的独立预览端口，只提供已验证的不可变产物

业务源码、密钥和运行时数据通过卷挂入，不打进镜像层。镜像里是 Agent 仓库的命令与页面，加上该业务声明的工具链。

存活与就绪分开：存活表示进程在；就绪表示锁、存储和关键配置可被安全读取。退出时先停止接收新任务，等待有限时间让当前步骤记下状态，再结束。中断的任务保留档案，不自动重做已写过的业务操作。

# 术语

| 术语 | 含义 |
| --- | --- |
| 实例 | 按本蓝图为一个业务实现的 Agent 仓库 |
| 绑定 | 该业务的仓库、运行时、验证、角色、模型和领域文档 |
| Host | 跑工作台和 Kernel 的常驻环境 |
| Kernel | 唯一执行任务状态变迁和业务仓写入的命令层 |
| 通道 | Web、IDE、工具协议或即时通讯。它们调用 Kernel |
| 迭代 / 任务 | 一次已开始的需求。目录是 `iterations/<id>/` |
| 需求卡 | 确认前的目标、范围、验收和影响面。确认后才入队 |
| 阶段产物 | 产品、界面、技术、用例、实施方案等全文 |
| 回执 | Kernel 记录的 approve、reject 或 comment，绑定产物版本 |
| 对齐 | 与写作者分开的上下游规则检查 |
| 功能分支 | `feat/<iteration-id>`，从当时的远端主干创建 |
| 基线 | checkout 时记录的 `origin/<baseBranch>` 提交号 |
| 已登记仓库 | 绑定里的 `targetRepositories`。之外的代码只读都需要另作允许，写入则禁止 |
| 写锁 | `runtime/workspace.lock`。持有者是 host 或某个人 |
| 队列 | 已确认、因 K1 尚未开始的需求 |
| 执行器 | 编码模型及其受控工具 |
| 接管 | 人持有写锁，执行器停止写入 |
| 交接 | 发布计划。不推送 |
| 外部阻塞 | 代码之外的权限、凭证或环境问题 |
| 提出人 | requester。描述需求、确认方案、验收 |
| 研发 | operator。审代码、接管、发布确认 |
| 活动投影 | `iterations/.active.md`。与锁冲突时锁获胜 |

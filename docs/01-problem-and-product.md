# 问题与产品

## 问题

一条业务改动需要三样东西同时在场：看懂需求的人、能改已登记仓库的执行者、以及在方案和发布点拍板的人。只把执行者放在某个研发的本地 IDE 里，会在下面几处断开：

| 能力 | IDE 开着 | IDE 关掉或机器休眠 |
| --- | --- | --- |
| 读代码、改代码 | 有 | 无 |
| 预览与验证 | 占着本机 | 无 |
| 过夜跑验证 | 不稳定 | 无 |
| 业务追问进度 | 没有任务对象 | 无 |
| 同时来两条需求 | 靠人记住 | 没有调度 |
| 换一台机器 | 状态在本地磁盘 | 上下文丢失 |

即时通讯适合短会话。一次改动要看方案全文、点同意、打开预览，卡片装不下；若在通讯适配器里再做一套阶段机，会和真正改仓库的内核分叉。

## 产品

给这个业务一个 **任务型 Web Agent**：

- 环境事先备在常驻 Host 上。提出人描述目标，不必安装工具链，不必先选仓库。
- 任务在后台继续。关掉浏览器只是放下遥控器。
- 人出现在决策点：确认需求、确认各阶段方案、验收、决定是否发布。
- 研发仍负责审代码、处理权限和外部阻塞、执行受控发布。产品把「卡在哪、要谁处理」写清楚。

界面对提出人使用业务语言：开始处理、方案等你确认、可以预览、正在排队。仓库名、分支名、命令名留在研发旁路和审计文件里。

## 角色

| 角色 | 能做 | 不能做 |
| --- | --- | --- |
| viewer | 看自己可见的任务状态 | 提需求、确认、改代码 |
| requester | 提需求、追问、确认或退回方案、验收、取消当前任务、移出尚未开始的排队项 | 推送保护分支、清除写锁、读取密钥、改写他人正在处理的任务 |
| operator | requester 的能力，加上审代码、接管写锁、发布确认、完成任务 | 代替模型跳过确认去改未授权文件 |
| admin | 放弃任务、在显式操作下切换活动迭代 | 用口头说明豁免闸门 |

同一个人可以兼角色。默认界面按提出人设计。

## 原则

1. **任务是一等公民。** 一次需求对应一条可恢复的任务，而不是聊天记录的副作用。问候、咨询、讨论思路不创建任务。
2. **人只在决策点出现。** 需要拍板时给出确认卡。没有回执，功能开发不开始。
3. **一个进行中。** 已有未收口任务时，新需求进入队列并说明原因，不覆盖当前任务。
4. **关页面不等于停工。** 状态在 Host 的文件里。
5. **影响面由需求决定。** 提出人不预选仓库。Agent 读取领域文档后判断，写进方案；人可以纠正。
6. **发布权留在人。** 默认只生成交接。保护分支推送需要 operator 的显式确认。
7. **维护必须有界。** 长期优化、周期巡检、以后再做的待办写在文档里。只有已授权的具体实施才占用进行中通道。巡检不得把已收口任务重新打开。

## 提出人主路径

1. 用访问凭证进入工作台。
2. 用自己的语言描述：谁在用、想改变什么、怎样算做完。
3. Agent 整理目标、范围、验收标准、影响仓库、是否涉及界面。有关键缺口才追问。
4. 提出人确认 **当前版本** 的需求卡。确认后才写入队列。Host 空闲才开始；忙碌时显示已确认、排队中、尚未开发。
5. 依次产出并确认：产品方案、必要的界面方案、技术方案、测试与验收用例、文件级实施方案。
6. 确认实施范围且执行器就绪后，Agent 在功能分支上修改允许的文件并运行已配置的验证。
7. 提出人逐项验收。通过后保存本地交付提交。
8. 若提出人要求发布，生成交接；只有额外的显式确认才接触保护分支。
9. 任务收口并释放通道。队列里的下一条默认等提出人开始，不静默开做。自动开始若打开，也只启动已确认的排队项，并且仍要重新确认方案后才改代码。

## 取消

取消进行中的任务是破坏性动作，需要两次主动确认：

1. 先说明将停止自动处理、未发布的改动不会上线、排队项不会自动开始、取消后不能在页面里一键恢复。默认按钮是返回并继续。
2. 再勾选已理解无法恢复，或复述任务标题中的关键词，然后才能确认取消。

取消后任务记为已放弃，写锁释放，已有分支和本地改动保留给研发处理。尚未开始的排队项可以一次确认后移出。已完成的任务不能取消。

## 成功标准

实例上线后看这些事实，而不是消息条数：

- 提出人能否独立走完「描述到确认方案」。
- 关掉页面后，任务是否仍在跑，或停在一张真实的确认卡上。
- 因为已有进行中任务而排队时，提出人是否能看懂等待原因。
- 保护分支是否从未被未经确认的发布碰到。

## 非目标

- 不做成面向任意公开仓库的通用编程助手。每个实例有明确的仓库允许列表。
- 不把即时通讯作为业务主入口。
- 不让提出人在网页里合并生产。
- 不并行改同一份可写工作副本。

# 编码运行时

编码运行时是受 Kernel 约束的执行器。它不是第二个可以改仓库的入口。

## 职责

| 组件 | 负责 | 不负责 |
| --- | --- | --- |
| 模型适配器 | 对话、工具调用、线程编号，便于停止后恢复 | 判断确认是否有效 |
| 编码工具服务 | 把模型的读写请求交给 Kernel | 不提供任意 Shell |
| Kernel | 校验锁、确认哈希、分支、路径、旧文件哈希、验证命令 | 不把模型的自由文本当成已执行的命令 |

每次调用前，编排器把下列材料注入上下文，而不是指望模型记得：

1. 实例 `AGENTS.md` 的摘要
2. `status` 的原始输出
3. 当前迭代的机器可读头和最近活动
4. 影响仓库列表
5. 本阶段允许的工具
6. K1–K10

## 写入条件

一次写入全部满足才执行：

- 本轮运行凭证有效，且锁的持有者是 host
- 需求版本、实施方案版本、对齐状态都是当前的 `passed` 或该阶段配置允许的已确认状态
- 仓库在 `repos[]` 内，当前分支是本期功能分支，基线提交与元数据一致
- 路径在已确认清单内，是允许的文本文件
- 调用方提供的旧文件哈希等于磁盘上的当前内容；不一致则拒绝，防止写到已变化的文件上
- 路径不越过仓库根，不是符号链接，不是环境文件、密钥或依赖目录

停止运行会撤销该凭证。已写的改动保留，运行记录和模型线程可恢复。停止后不得继续用旧凭证写入。

默认自动写入范围是已确认清单中的实现与测试文本文件。依赖清单、锁文件、构建与发布配置、迁移脚本，需要在实施方案里逐项出现并确认。

## 验证命令

验证命令由维护者配置在每个仓库上：命令、参数、环境、超时、可选的产物目录。模型不能提交另一条命令来代替。

结果绑定当前文件内容指纹。验证后文件再变，旧结果作废，不能用于交付。

失败、超时、零用例、全部跳过、环境与记录不符，都不能当成通过。构建成功不等于测试通过，测试通过不等于业务验收通过。

尚未交付时，Kernel 在一轮实现结束后检查本版本是否缺少或过期的验证。最多自动继续有限轮次（默认 2）做定位、修复和复验。沿用原凭证、时限和文件范围。相同源码与相同失败则停止。停止、确认失效或已经交付之后，不再自动继续。

「只补跑验证、不改代码」是单独入口：不调用编码模型，不改历史交付和确认，也不因为补跑通过就自动验收。

## 人机接管

| 模式 | 谁可以写业务仓 |
| --- | --- |
| Host 持有 | 编码运行时 |
| 人接管 | 指定的人。页面显示自动处理已暂停 |
| 禁止 | 两边同时写 |

接管用显式命令切换锁的持有者。恢复给 Host 前，工作区必须干净，或由人明确处理完脏文件。

研发日常审查使用远端功能分支上的另一份 clone，不和 Host 共用磁盘工作区。

## 系统提示里的禁令

编码模型的工具面不包含：

- 自行 `checkout`、`push`、`reset`、改 Git 配置
- 自行创建或完成迭代
- 自行写入确认回执
- 任意 Shell、任意网络请求、读取环境文件

需要这些效果时，只能走已注册的 Kernel 工具，由 Kernel 再决定拒绝或执行。

## 就绪

`automaticCoding` 为真，只表示执行器允许在闸门通过后工作。下列任一项不成立，开发阶段停住并说明原因：

- 模型接口未配置或不可用
- 实施方案未确认或对齐不是当前版本
- 功能分支不在预期提交上
- 该仓库没有配置验证命令，而本次交付声明需要验证
- 写锁不属于 host

设计阶段可以在执行器未就绪时继续。界面必须把「设计」和「正在改代码」分开。

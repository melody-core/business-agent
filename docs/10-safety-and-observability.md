# 安全与可观测

## 路径

- 编码运行时的工作根是 Agent 仓库。
- 业务写入只能落到已登记的 `target-repos/<key>`。
- 拒绝 `../` 越出仓库、符号链接、环境文件和非代码的密钥材料。
- 只读检索若存在，同样使用允许列表，并基于已提交的 Git 对象。未提交内容、空仓库和符号链接不启用。分析必须说明这个提交不等于已部署版本。

## Git

命令封装拒绝：

- 向保护分支 push（发布确认除外）
- 没有迭代确认的破坏性回滚
- 修改全局 Git 配置
- force push
- 删除仓库元数据

业务仓的提交由 Kernel 在验收通过后执行，消息说明这次改动的目的。

## 密钥

- 模型、访问口令和上游凭证只经环境变量进入进程。配置文件写变量名，不写值。
- 落盘的会话与令牌加密保存，目录与文件仅所有者可访问。
- 日志、事件、活动记录、对齐报告、错误响应都不复制令牌、Cookie、授权码、请求正文和模型密钥。
- Agent 若需判断「是否已配置」，只查询名字是否存在。
- `.env` 不进入版本库，不进入镜像构建上下文。

错误对提出人显示请求编号和可行动的说明。内部错误只保留类型、错误码和代码位置。

## 审计

每次 Kernel 调用、登录成败、确认、队列变化、验证和发布尝试都有事件。HTTP 响应带头返回请求编号，后续模型、工具和子进程沿用它。

统一运行日志与事件分开：

- 事件是状态变迁，可用来恢复进度。
- 运行日志是诊断，有大小上限并轮转。
- 写入日志失败只告警，不改变业务是否成功的判定；若审计事件写失败，则当前有副作用的命令失败，避免出现「仓库已改但没有记录」。

## 红线

下列动作没有单独的、带确认的 Kernel 命令，模型工具不得执行：

- 删除 `.git`
- 递归删除仓库或运行时目录
- 修改全局凭据或全局 Git 配置
- force push
- 读取并外发环境文件
- 在未登记仓库写入

## 依赖与供应链

Agent 仓库的依赖与业务仓的依赖分开安装。业务仓使用它自己声明的语言版本和依赖源。工具链版本写在绑定里，镜像或 Host 按绑定准备，而不是假定某一种语言版本适用于所有仓库。

编码运行时和模型适配器的版本固定在实例中。升级是一次 Agent 仓库的变更，不是运行中的隐式漂移。

## 可观测的最小集合

`status` 至少给出：

- 活动迭代 id、标题、阶段、状态
- 锁的持有者、心跳时间、是否陈旧
- 当前身份可见的队列长度
- Host 是否在心跳窗口内
- 执行器是否就绪（不含密钥）

提出人页面用业务语言显示同一事实的子集。

## 恢复

| 场景 | 行为 |
| --- | --- |
| 陈旧锁 | 告警，不自动抢 |
| 双持有者 | 拒绝后写者 |
| 模型声称完成但没有产物 | 阶段保持原状 |
| 预览校验和不符 | 不提供该地址 |
| 对话进程崩溃 | 已落盘轮次可重试，不把半截回复标成方案已提交 |

## 可选的只读证据

有些业务能提供日志、追踪或知识检索。这是可选模块，默认关闭。

打开时：

- 语义规划只返回路线，不写仓库。
- 执行层校验参数、身份和只读工具名单。
- 凭证留在服务端会话，不进入模型上下文、历史或证据正文。
- 工具失败时说明缺失，不改用关键词假装查过。
- 证据带编号、来源、范围、哈希和截断标记。结论和推测分开。
- 没有实际证据时不编造规则。
- 从证据生成修复需求时，复用同一 Kernel。来源范围和源码版本随需求保存。方案确认前不改代码。

没有证据源时，不显示排障入口，也不要求提出人先连接身份系统才能做普通需求。
